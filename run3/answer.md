# SOC / CSIRT初動調査演習 模範解答・解説資料

> **演習担当者専用**  
> 本資料は、演習中の軽い解答確認、全体解説、振り返りで使用する。状況付与前に受講者へ配布しない。特に、後続状況付与の内容、侵害・認証・ファイル操作等に関する未確認事項を先回りして教えない。

## 1. 演習の学習目標

本演習では、SOC / CSIRT配属直後の初任者が、状況付与、ネットワーク構成図、`training.pcap` をもとに次を実践できることを目標とする。

- 攻撃・異常の可能性がある通信の流れを時系列で整理する。
- 初動調査で確認すべき事項を、観測事実と追加確認事項に分ける。
- PCAPで直接確認できる事実と、推測・未確認事項を分離する。
- PCAPだけでは認証、端末状態、ファイル操作、情報窃取、暗号化等を断定できないことを理解する。
- 追加で必要なログ、端末・サーバー情報、正規作業情報を具体化する。
- 影響拡大の抑制と証跡保全の両方を意識して初動対応案を整理する。
- SOC / CSIRT内で、事実・不確実性・必要な判断を明確にして共有・エスカレーションする。

## 攻撃シナリオの概要

### シナリオ全体の要約

元の公開インシデント報告書からStep 1で抽出した要点は、ランサムウェア事案が複数のプリンタ出力を契機に発覚し、端末・サーバーのデータ暗号化が発生し、初期侵入経路としてVPN装置の脆弱性悪用が疑われたこと、また内部で複数端末・サーバーへのアクセスが確認されたことである。

本演習では、この事案をそのまま再現せず、Shimada Laboratoryのネットワーク構成へ抽象化している。**演習上の仮定**として、まずUTM(VPN)公開側への通常より多い外部通信を観測し、その後、VLAN40のIT支援端末 `IT-PC-01` からAD、ファイル共有、複数部門端末への通信が目立つ。続いて複数部門から `FILE-SRV-01` へのSMB通信が増え、共有フォルダ利用に関する問い合わせが発生する。最後に、通信の継続・再試行と業務影響を踏まえ、初動対応と共有判断を整理する。

この一連の流れは、**侵入成功や横展開成功をPCAPで証明するシナリオではない**。PCAPで観測できる通信パターンを起点に、追加証跡を要求し、断定を避けながら調査範囲と初動判断を組み立てるための教材である。

### PCAPで確認できる範囲

`training.pcap` では、以下を通信事実として確認できる。

- 送信元・宛先IPアドレス。
- 通信時刻と大まかな時系列。
- TCP / UDP、宛先ポート、通信方向。
- 同一または類似通信の回数・頻度・継続性。
- 複数セグメントをまたぐ通信先の広がり。
- TCP接続の再試行や、一部のリセット応答の存在。
- 通常相当の比較通信と、相対的に目立つ通信の違い。

実ファイルでは、外部ベースライン通信の後に `198.51.100.23` から `203.0.113.11:443` への複数接続がまとまって現れ、その後 `IT-PC-01` の内部通信、複数部門から `FILE-SRV-01:445` への通信集中、さらに再試行・リセットを含む通信が続く構成になっている。

### PCAPだけでは断定できない範囲

以下は、PCAPの通信存在だけでは確定しない。

- VPN認証の成功・失敗。
- VPN装置の脆弱性悪用、認証情報窃取、内部侵入の成否。
- AD認証または内部端末へのログオン成功。
- IT-PC-01や他端末の侵害、権限昇格。
- 端末上で実行されたコマンド、プロセス、攻撃ツール、マルウェア。
- FILE-SRV-01上のファイル閲覧、コピー、削除、内容変更。
- 情報窃取。
- ファイル暗号化の実行・成功。
- 業務影響の根本原因。
- 最終的な侵害範囲、攻撃成功、攻撃者の意図。

### 解説時に強調する点

1. **「通信がある」ことと「操作・認証が成功した」ことは別の事実である。**
2. **通信パターンは調査優先度を上げる根拠にはなるが、侵害確定の根拠にはならない。**
3. **ユーザ報告は重要な事実だが、原因はPCAPとは別証跡で裏付ける必要がある。**
4. **初動では、確定していない原因探しより、証跡保全、影響範囲確認、追加ログ要求、必要な封じ込め判断を優先する。**
5. **演習上の外部IP、公開IP、外部ホスト名は文書化・演習用であり、実在資産を示さない。**

## 2. 攻撃シナリオと状況付与の対応

本演習の「攻撃の流れ」は、あくまで運営上のシナリオ整理である。受講者の模範回答では「侵入した」「横展開した」「暗号化した」と断定するのではなく、「その可能性を調査すべき通信パターンが観測されている」と表現する。

| 段階 | 観測・状況付与 | 運営者が持つ仮説 | 受講者に求める表現 |
|---|---|---|---|
| 1 | UTM(VPN)への外部443通信増加 | 境界から始まる侵害疑いを想定 | 「通常外と評価すべき外部通信がある。認証・侵入成否は未確認」 |
| 2 | IT-PC-01からAD / File Share / 複数端末への通信 | 内部活動の広がりを想定 | 「複数宛先・管理系サービスへの通信がある。ログオン・侵害は未確認」 |
| 3 | 複数部門からFILE-SRV-01へSMB通信が集中 | 共通サービス周辺の影響を想定 | 「SMB通信増加と利用者報告がある。ファイル操作・暗号化は未確認」 |
| 4 | 業務影響が複数部門へ広がり、再試行通信も観測 | 重大度上昇と封じ込め検討を想定 | 「影響拡大の可能性があり、保全と封じ込め候補を上位者へ提示」 |
| 5 | 新規技術情報なし | 初動判断の統合 | 「事実・推測・未確認事項を明示し、次の調査と対応を引き継ぐ」 |

## 3. 状況付与ごとの模範解答

### INJ-01：境界VPNへの通常外通信

#### この時点で確認できる事実

- 状況付与では、UTM(VPN)公開側への外部接続が通常より多いとされている。
- PCAPには `198.51.100.23` から `203.0.113.11` のTCP/443への複数接続があり、比較用の `198.51.100.24` からの通信より頻度が高い。
- `203.0.113.11` はネットワーク定義上 `UTM-VPN-01` の公開側である。
- 通信方向は外部から自組織側公開アドレスへの内向きである。

#### 推測にとどめるべきこと

- 正規保守ではない可能性、異常な接続試行である可能性。
- 後続の内部通信と関係する可能性。
- インシデントの初期兆候である可能性。

#### まだ断定できないこと

- VPN認証の成功・失敗。
- 有効なアカウントが使用されたか。
- VPN装置の脆弱性が悪用されたか。
- 認証情報が窃取されたか。
- 内部ネットワークへ侵入したか。

#### PCAPで確認すべき通信

- F-001 / `TR-INJ01-001`：`198.51.100.23` → `203.0.113.11` HTTPS/TCP 443。
- F-002 / `TR-INJ01-002`：`198.51.100.24` → `203.0.113.11` HTTPS/TCP 443（比較用）。
- 比較観点は、送信元、宛先、方向、接続頻度、時系列である。

#### 追加確認が必要な情報

- UTM/VPN認証ログ：接続元別の成功・失敗、アカウント、時刻。
- UTM/VPNのセキュリティログ、設定変更履歴、ログ保全状況。
- IT管理者・保守ベンダーの正規作業予定、変更申請、許可接続元。
- 対象時間帯以降の内部通信や端末・サーバー側の関連ログ。

#### 初動対応・共有の模範

- 境界装置の関連ログを上書きされないよう保全する。
- 正規保守かを速やかに照合する。
- 異常性が否定できないため、SOC / CSIRT内で「外部通信増加を観測、認証・侵入成否は未確認」と共有する。
- 直ちに「侵入済み」と断定して全停止するのではなく、追加証跡を確保しつつ、組織手順に従って接続制限等の要否を上位者へ相談する。

#### 軽い解答確認で受講者に確認するポイント

- 「通信の存在」と「認証成功」を分けているか。
- 外部IPの回数・方向・宛先を具体的に挙げられているか。
- VPN認証ログと正規保守照合を追加確認に挙げているか。

#### 議論が脱線した場合の戻し方

「PCAPのどのフィールドから、認証成功と判断できますか」と問い、送信元・宛先・ポート・回数までは見えるが認証判定は見えない点へ戻す。

#### 次の状況付与に進むために揃えておきたい認識

**外部からVPN公開側への通常外通信は調査すべき事実だが、認証成功・侵入成功は未確認である。次は内部側で関連し得る通信がないかを確認する。**

#### この時点で直接教えてはいけない情報

認証成功、VPN侵害、認証情報窃取、脆弱性悪用、攻撃者の意図、後続のIT-PC-01の通信内容。

### INJ-02：IT支援端末からの内部通信増加

#### この時点で確認できる事実

- `IT-PC-01 (192.168.40.1)` から `AD-SRV-01 (192.168.100.1)` へTCP/88、389、445の通信がある。
- `IT-PC-01` から `FILE-SRV-01 (192.168.100.2)` へTCP/445の通信がある。
- `IT-PC-01` から `ACC-PC-03 (192.168.20.3)` へTCP/445、135の通信がある。
- `IT-PC-01` から `DEV-PC-07 (192.168.50.7)` へTCP/3389の通信がある。
- 比較用として `GA-PC-01` からADへのTCP/88、File ShareへのTCP/445の通常相当通信も存在する。
- VLAN40からVLAN100、VLAN20、VLAN50へ複数宛先に通信が広がっている。

#### 推測にとどめるべきこと

- IT-PC-01を優先調査対象にすべき可能性。
- 正規のIT管理作業ではなく、内部での不審な活動である可能性。
- いわゆる水平展開に似た通信パターンである可能性。

#### まだ断定できないこと

- AD認証・SMB認証・RDPログオンの成功。
- IT-PC-01または通信先端末の侵害。
- 権限昇格、認証情報窃取。
- 端末上での具体的コマンドや攻撃ツールの実行。
- ファイルの閲覧・変更。

#### PCAPで確認すべき通信

- F-003 / `TR-INJ02-001`：IT-PC-01 → AD-SRV-01 Kerberos/88。
- F-004 / `TR-INJ02-002`：IT-PC-01 → AD-SRV-01 LDAP/389。
- F-005 / `TR-INJ02-003`：IT-PC-01 → AD-SRV-01 SMB/445。
- F-006 / `TR-INJ02-004`：IT-PC-01 → FILE-SRV-01 SMB/445。
- F-007 / `TR-INJ02-005`：IT-PC-01 → ACC-PC-03 SMB/445。
- F-008 / `TR-INJ02-006`：IT-PC-01 → DEV-PC-07 RDP/3389。
- F-009 / `TR-INJ02-007`：IT-PC-01 → ACC-PC-03 TCP/135。
- F-010 / `TR-INJ02-008`、F-011 / `TR-INJ02-009`：GA-PC-01からAD / File Shareへの比較用通信。

#### 追加確認が必要な情報

- AD認証ログ、Windowsイベントログ、RDP/SMBサービス側ログ。
- IT-PC-01のEDR / アンチウイルスログ、プロセス実行履歴。
- IT Supportの作業記録、変更申請、保守作業の有無。
- UTM/VPNの接続情報と、IT-PC-01の通信時系列の照合。
- アカウント・グループ変更履歴。

#### 初動対応・共有の模範

- IT-PC-01を「侵害確定端末」ではなく**優先調査・隔離候補**として扱う。
- IT-PC-01およびAD / File Shareの関連ログを優先保全する。
- 正規IT作業かを確認する。
- 通信範囲が複数VLANに広がっているため、SOC / CSIRT内の優先度を引き上げ、上位者へ「内部通信拡大を観測、ログオン・侵害成否は未確認」と共有する。

#### 軽い解答確認で受講者に確認するポイント

- 「水平展開が成功した」と断定せず、「水平展開を疑わせる通信」と表現できているか。
- AD-SRV-01、FILE-SRV-01の役割を構成図から説明できるか。
- 正常比較通信とIT-PC-01の複数宛先通信を比較しているか。
- 端末・認証ログが必要と理解しているか。

#### 議論が脱線した場合の戻し方

攻撃ツール名やコマンドの推測に寄った場合、「その情報はPCAPのどこに含まれていますか」と問い、IP、ポート、方向、回数の観測事実へ戻す。

#### 次の状況付与に進むために揃えておきたい認識

**IT-PC-01から複数の内部重要資産・端末への通信が観測され、調査優先度は上がる。ただしログオン成功・端末侵害は未確認である。**

#### この時点で直接教えてはいけない情報

IT-PC-01の侵害確定、ログオン成功、認証情報窃取、コマンド実行、攻撃ツール利用、後続のファイル影響。

### INJ-03：共有ファイル周辺の通信増加

#### この時点で確認できる事実

- `GA-PC-03`、`ACC-PC-03`、`SALES-PC-03`、`DEV-PC-07`、`IT-PC-01` から `FILE-SRV-01:445` への通信が観測される。
- 複数部門からFILE-SRV-01へのSMB通信が集中している。
- `GA-PC-03` から `AD-SRV-01:88` の通常相当認証関連通信も存在する。
- 状況付与では、共有フォルダ表示の遅延、普段と異なるファイル名、開けないファイルがあるという利用者問い合わせが提示されている。
- PCAPの通信事実と利用者報告は別々の証拠であり、時系列・対象範囲を突き合わせる必要がある。

#### 推測にとどめるべきこと

- FILE-SRV-01または共有サービス周辺で何らかの異常が起きている可能性。
- INJ-02の内部通信と関連する可能性。
- 共有サービスが共通影響点になっている可能性。

#### まだ断定できないこと

- ファイル閲覧、コピー、削除、名称変更、内容変更。
- 情報窃取。
- マルウェア実行や暗号化実行。
- 「開けないファイル」の原因。
- 利用者報告とSMB通信増加の因果関係。

#### PCAPで確認すべき通信

- F-012〜F-016：GA / Accounting / Sales / Development / IT Support端末からFILE-SRV-01へのSMB/445。
- F-017：GA-PC-03からAD-SRV-01へのKerberos/88比較通信。
- 送信元部門の広がり、FILE-SRV-01への集中、通信の継続性を確認する。

#### 追加確認が必要な情報

- FILE-SRV-01の監査ログ、SMB / ファイル共有ログ。
- ファイル変更履歴、アクセス履歴、対象ファイルのメタデータ。
- 利用者問い合わせの対象ファイル・発生時刻・利用端末。
- EDR / アンチウイルスログ、端末・サーバーイベントログ。
- バックアップの稼働状態、世代、復元可否、直近正常状態との差分。
- 必要に応じて外部向け通信ログを確認し、情報持ち出しの有無を別途検証する。

#### 初動対応・共有の模範

- FILE-SRV-01のログ、監査証跡、バックアップ状態を優先保全・確認する。
- 影響部門と対象ファイルを具体化し、業務影響の範囲を整理する。
- IT-PC-01等の優先調査候補とFILE-SRV-01の関係を時系列で整理する。
- 「情報窃取・暗号化が起きた」とは報告せず、「複数部門からSMB通信増加と共有ファイル利用異常の報告がある。ファイル操作の内容は未確認」と共有する。

#### 軽い解答確認で受講者に確認するポイント

- SMB通信増加をもって情報窃取・暗号化と断定していないか。
- 利用者報告とPCAP事実を分けているか。
- FILE-SRV-01の監査ログとバックアップ確認を挙げられているか。

#### 議論が脱線した場合の戻し方

「PCAPからファイルの中身や暗号化後の状態を確認できていますか」と問い、ネットワーク通信とファイルシステム証跡の違いへ戻す。

#### 次の状況付与に進むために揃えておきたい認識

- 事象・実施対応・時刻の記録を一元化。

この時点では、複数部門で業務影響が継続し、重要内部サービス周辺で通常外と考えられる通信が複数段階にわたり観測されているため、**SOC / CSIRT内の上位者・インシデント責任者へ優先度高くエスカレーションするのが妥当**である。

- 未確認：認証成功、端末侵害、ファイル操作、情報窃取、暗号化、根本原因。
- 直ちに必要：ログ保全、正規作業照合、影響範囲確認、隔離・接続制限の判断。

- 証跡保全を伴う対応になっているか。
- 「全部停止」「全部初期化」等に飛躍していないか。
- エスカレーション文に、事実と未確認事項が明示されているか。

**重大度を上げて初動対応を検討するだけの事実はそろっているが、原因や侵害範囲の確定はまだできない。証跡保全・封じ込め候補・追加ログ・エスカレーションをセットで整理する。**

## 4. 攻撃の流れの整理

演習上の通信タイムラインは以下のように読む。

```text
外部ホスト → UTM-VPN-01:443
   ↓  「通常外通信」だが認証・侵入は未確認
IT-PC-01 → AD / FILE / ACC-PC-03 / DEV-PC-07
   ↓  「内部通信拡大」だがログオン・侵害は未確認
複数部門端末 → FILE-SRV-01:445
   ↓  利用者から共有ファイル利用異常の報告
AD / FILE周辺の継続・再試行・一部RST

最終メモ：事実・推測・未確認事項を分離して引継ぎ
```

この流れは「攻撃が成功したこと」を示すものではない。**通信面の相関を仮説化し、追加ログで検証するための初動ストーリー**である。

## 7. 初動対応案

初動対応は、原因確定を待たずに実施できる「保全・確認」と、影響が大きいため上位判断が必要な「封じ込め候補」を分ける。

### 直ちに優先したい保全・確認

- PCAP、UTM/VPN、AD、FILE-SRV-01、対象端末の関連ログを保全する。
- 事象、実施対応、判断、時刻を一元記録する。
- 正規作業・保守作業を照合する。
- 利用者影響を部門・機能・端末・時刻で整理する。
- IT-PC-01等の調査優先端末を明確化する。

### 上位者と判断する封じ込め候補

- 調査優先端末のネットワーク隔離。
- UTM/VPNの接続元制限、停止、許可リスト化等。
- 必要なアカウント・VPN認証情報の変更。
- FILE-SRV-01 / ADのアクセス制限や代替運用。
- 専門家・インシデント対応支援の要請。

### 避けたい初動

- 証跡保全前の一律初期化。
- 理由なく全端末を電源断すること。
- 「ランサムウェア確定」「情報漏えい確定」等の未確認断定を前提に対応範囲を固定すること。
- PCAPだけで原因を決め打ちし、追加ログの取得を止めること。

## 8. SOC / CSIRT内でのエスカレーション判断

エスカレーションは「確定した攻撃名」ではなく、**影響、観測範囲、重要資産、未確認事項、必要な上位判断**で判断する。

INJ-01では注意喚起・追加調査開始、INJ-02では内部通信拡大により優先度を上げる、INJ-03では共通サービスと利用者影響によりインシデント扱いを強める、INJ-04では複数部門影響と重要サービス周辺の継続通信を理由に上位者へ優先エスカレーション、INJ-05では引継ぎ可能な初動メモとして整理するのが模範である。

共有メッセージは「確認済み」「未確認」「実施済み」「判断依頼」を分ける。

### SOC / CSIRT内で共有・エスカレーションすべき内容

- 複数段階にわたる通常外通信と複数部門の業務影響があるため、インシデント責任者へ優先エスカレーション。
- 認証成功・侵害・情報窃取・暗号化は未確認であることを明示。
- ログ保全、隔離候補、VPN制限、認証情報変更等について上位判断を求める。

### 判断理由

単一通信ではなく、境界、内部重要サービス、複数部門、業務影響という複数の独立した観測が時系列で重なっており、追加調査と影響抑制の優先度を上げる合理的根拠がある。一方、PCAPだけでは侵害や認証・ファイル操作を確定できないため、断定は避ける。

## 10. 初任者が間違えやすい点

| 誤り | 修正する考え方 |
|---|---|
| VPN装置への外部通信があるので侵入成功 | 通信の存在とVPN認証・侵入成功は別。装置ログが必要。 |
| IT-PC-01から複数端末へ通信しているので横展開成功 | 通信拡大は重要な兆候だが、ログオン成功・侵害は未確認。 |
| RDP / SMBがあるので特定コマンドや攻撃ツールが実行された | ネットワークポートから端末上のプロセスは確定できない。 |
| FILE-SRV-01へのSMB増加＝ファイル窃取・暗号化 | ファイル操作の意味は監査・ファイルシステム・端末ログが必要。 |
| TCPリセット＝マルウェアによるサービス停止 | リセットは通信上の事実。原因は障害・設定・正規作業等もあり得る。 |
| 初動では全端末停止・初期化が安全 | 影響抑制と証跡保全を両立し、組織手順と上位判断で隔離する。 |
| 最終メモでは原因を一つに断定すべき | 初動メモでは事実・推測・未確認事項を分け、検証可能な形で引き継ぐ。 |

## 11. 全体解説での締めのポイント

受講者に残したい結論は、「PCAPで攻撃名を当てる」ことではない。通信事実から調査対象と優先度を定め、PCAPの限界を明示し、追加証跡へ進み、証跡保全と影響抑制を両立させながら、上位者が判断できる情報に整理することがSOC / CSIRT初動の基本である。
