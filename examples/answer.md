# SOC / CSIRT初任者向け 初動調査演習 模範解答

> **用途**：演習担当者向けの解答・解説資料です。受講者への事前配布は想定していません。  
> **根拠**：`design.xlsx`、`cards.pptx`、`question.md`、`network.json`、`pcap_design.json`、`answer_key.json`、`training.pcap` に基づきます。  
> **重要**：本演習では、PCAPに通信が存在することと、認証・侵害・ファイル操作・情報窃取・暗号化などが成功したことを分けて扱います。

---

## 1. 演習の学習目標

受講者が、状況付与と通信証跡をもとに、次の事項を初動調査として整理できることを目標とします。

- 攻撃またはインシデントの流れを、確認済み事実と仮説に分けて整理する。
- 初動調査で優先して確認する資産・ログ・端末を整理する。
- PCAPで直接確認できる通信事実と、PCAPだけでは分からない事項を切り分ける。
- 認証成功、ファイル操作、情報窃取、暗号化などを、不十分な証拠から断定しない。
- 追加で必要となるログや端末調査を具体化する。
- 影響拡大の可能性と業務影響を踏まえ、初動対応案をまとめる。
- SOC / CSIRT内で共有・エスカレーションすべき内容を、確定事項と未確定事項に分けて伝える。

---

## 2. 攻撃シナリオの概要

### シナリオ全体の要約

公開インシデント報告書から前Stepで抽出した要点は、**ランサムウェアにより業務システムが利用不能となり、複数端末・サーバーへ影響が生じたこと**、および**VPN装置経由の初期侵入や内部での水平展開が疑われたこと**です。

本演習では、その要点を一般的な社内ネットワークへ写像しています。演習上は、インターネット境界の `UTM-VPN-01` への外部接続増加を起点に、内部の `AD-SRV-01` と `FILE-SRV-01` への通信増加、`IT-PC-02` と `DEV-PC-03` を送信元候補とする複数セグメントへの通信、ファイル共有通信と外部HTTPS通信の近接、最後に共有ファイル利用障害などの業務影響申告へ進みます。

ただし、この一連の流れが実際に一人の攻撃者による侵害活動であり、ランサムウェア実行や情報窃取に成功したことをPCAPだけで証明する設計ではありません。受講者には、**「通信上の事実を積み上げ、仮説を持ちながらも、成功や原因の断定には追加証拠が必要である」**という初動調査の考え方を身につけてもらいます。

#### 公開報告書由来と演習上の仮定の区別

| 区分 | 本演習で扱う内容 |
|---|---|
| `report_fact` | 元事案ではランサムウェアにより業務システムが利用不能となり、複数端末・サーバーに影響が生じた。 |
| `inferred_from_report` | 元事案を踏まえ、VPN装置を入口候補、内部サービス・複数端末への通信を水平展開候補として写像する。 |
| `network_topology` | UTM(VPN)、VLAN100のAD・ファイルサーバ、VLAN10〜50の部門端末という既存ネットワークを使用する。 |
| `exercise_assumption` | 外部ホスト、IT-PC-02 / DEV-PC-03を中心にした通信増加、FILE-SRV-01へのSMB増加、外部HTTPS通信などを演習用に配置する。 |

### 状況付与と攻撃段階の対応

| 状況付与 | 攻撃段階 | 受講者に考えさせたいこと |
|---|---|---|
| INJ-01 | 外部接続の初期観測 | 外部→UTM(VPN)通信の存在と、VPN認証・侵害成功を分ける。 |
| INJ-02 | 重要内部サービスへの通信増加 | AD・ファイルサーバへの通信と、認証成功・ファイル操作成功を分ける。 |
| INJ-03 | 横方向通信候補 | 複数セグメントへの通信先拡大を捉えつつ、横展開成功やコマンド実行を断定しない。 |
| INJ-04 | ファイル共有と外部通信の近接 | 時系列の相関を調査材料としつつ、情報窃取という因果を断定しない。 |
| INJ-05 | 業務影響の顕在化 | 原因未確定でも、証跡保全、影響範囲整理、隔離候補、共有・エスカレーションを判断する。 |

### PCAPで確認できる範囲

- 送信元IP、宛先IP
- 通信時刻と前後関係
- TCP / UDPなどの通信種別
- 宛先ポート
- 通信方向
- 通信の有無
- 同一通信組み合わせの相対的な回数・継続
- UTM(VPN)公開側への外部通信
- AD-SRV-01 / FILE-SRV-01への通信
- 複数部門端末へのSMB / RDP / TCP 5985通信
- 内部端末から演習用外部ホストへのHTTPS通信

`training.pcap` を直接確認した結果、ファイルには **1,582パケット**が含まれ、`answer_key.json` の31件の `pcap_observable_findings` が参照する通信組み合わせを確認できます。PCAP内の `traffic_id` は設計上の識別子であり、パケット自体にIDラベルが埋め込まれているわけではありません。

### PCAPだけでは断定できない範囲

- VPN認証の成功・失敗
- VPN装置の脆弱性悪用や資格情報利用の成立
- AD認証の成功・失敗、対象アカウントの確定
- 資格情報窃取、AD設定変更
- ファイル閲覧、コピー、削除、暗号化
- RDP等のリモートログオン成功
- 端末上のコマンド、プロセス、マルウェア実行
- 権限昇格、横展開成功
- 外部HTTPS通信の内容と情報窃取の有無
- プリンタ警告文の生成元・印刷原因
- 攻撃者の意図

### 解説時に強調する点

1. **ポートが見えることと、処理が成功したことは別である。**
2. **時系列上の近接は重要な相関だが、因果関係の証明ではない。**
3. **「分からない」で終わらず、何を追加確認すれば判断できるかまで言語化する。**
4. **原因未確定でも、影響拡大リスクや業務影響を根拠に初動対応・エスカレーションは検討できる。**
5. **PCAPは補助証跡であり、端末・認証・サーバ・境界装置のログを組み合わせて判断する。**

## 3. 攻撃シナリオと状況付与の対応

演習担当者は、以下を「確定した攻撃事実」ではなく、**段階的に強まる調査仮説**として扱ってください。

1. UTM(VPN)公開側に、比較用通信より高頻度な外部HTTPS通信が観測される。
2. その後、演習上のUTM(VPN)内部側表現からAD・ファイルサーバへの通信が観測される。
3. IT-PC-02 / DEV-PC-03からAD・FILE-SRV-01への通信が増え、さらに複数VLANの端末へのSMB / RDP / 管理系通信が観測される。
4. FILE-SRV-01へのSMB通信と近い時間帯に、IT-PC-02 / DEV-PC-03から外部ホストへのHTTPS通信が観測される。
5. 複数部署から共有ファイル利用障害が申告され、プリンタに警告文のような出力があったという連絡が入る。

この連鎖から、演習上は「外部からの侵害、内部展開、外部通信、ランサムウェア様の業務影響」を疑うことが合理的です。ただし、**個々の成功状態と原因は追加ログ・端末調査で確認する必要があります。**

# 4. 状況付与ごとの模範解答

## 4.1 INJ-01：UTM(VPN)への不審な外部接続

### この時点で確認できる事実

- `203.0.113.45` と `203.0.113.46` から `UTM-VPN-01 (198.51.100.11)` のHTTPS/443への反復通信が観測される。
- 比較用の `203.0.113.20` からも同じ宛先への通信があるため、「外部から443通信があること」自体のみで異常とは言い切れない。
- 反復外部通信の後に、演習上のUTM(VPN)内部側表現 `192.168.100.254` から `AD-SRV-01` へのDNS/53、Kerberos/88、LDAP/389、および `FILE-SRV-01` へのSMB/445通信が観測される。
- 状況付与上、現時点でVPN認証成功や侵害は確認されていない。

### 推測にとどめるべきこと

- 外部接続増加が攻撃目的の接続である可能性。
- 外部接続と内部サービス向け通信が同じ主体・同じセッションに関連する可能性。
- UTM(VPN)が侵入経路になった可能性。

### まだ断定できないこと

- VPN認証が成功したか。
- 脆弱性悪用や資格情報利用が成立したか。
- 外部ホストが実際の攻撃者か。
- 後続の内部通信が外部接続と同一主体によるものか。

### PCAPで確認すべき通信

| Finding | Traffic ID | 確認対象 |
|---|---|---|
| F-001 | TR-INJ01-001 | `203.0.113.45 → 198.51.100.11` HTTPS/443 |
| F-002 | TR-INJ01-002 | `203.0.113.46 → 198.51.100.11` HTTPS/443 |
| F-003 | TR-INJ01-003 | 比較用 `203.0.113.20 → 198.51.100.11` HTTPS/443 |
| F-004 | TR-INJ01-004 | `192.168.100.254 → AD-SRV-01` DNS/53 |
| F-005 | TR-INJ01-005 | `192.168.100.254 → AD-SRV-01` Kerberos/88 |
| F-006 | TR-INJ01-006 | `192.168.100.254 → AD-SRV-01` LDAP/389 |
| F-007 | TR-INJ01-007 | `192.168.100.254 → FILE-SRV-01` SMB/445 |

### 追加確認が必要な情報

- UTM/VPN認証ログ：成功・失敗、接続元IP、対象アカウント、時刻。
- UTM/VPNセッションログ：セッションID、内部側割当情報が存在する場合はその情報。
- UTM/VPN装置ログ・設定変更履歴・ログ保全状況。
- 各機器の時刻同期状況。

### 軽い解答確認で受講者に確認するポイント

- 「外部から通信があった」ことと「VPN認証に成功した」ことを分けているか。
- 比較通信を見て、通信の有無だけでなく頻度や前後関係を観察しているか。
- 追加確認としてVPN認証・セッションログを挙げられているか。
- 現時点では「侵害確定」と表現していないか。

### 議論が脱線した場合の戻し方

「PCAPから直接言えるのは、誰からどこへ、いつ、どのポートで通信があったかです。認証結果はどの証跡で確認しますか」と問い、観測事実へ戻します。

### 次の状況付与に進むために揃えておきたい認識

- UTM(VPN)は優先確認対象である。
- 外部通信増加は重要な兆候だが、侵害成功は未確認である。
- AD・ファイルサーバへの通信が見えているため、内部側の追加調査が必要である。

## 4.2 INJ-02：内部サービスへの通信増加

### この時点で確認できる事実

- `IT-PC-02 (192.168.40.2)` から `AD-SRV-01` へのDNS/53、Kerberos/88通信が観測される。
- `DEV-PC-03 (192.168.50.3)` から `AD-SRV-01` へのLDAP/389、SMB/445通信が観測される。
- IT-PC-02とDEV-PC-03から `FILE-SRV-01` へのSMB/445通信が観測される。
- 比較用として、`GA-PC-01` からAD-SRV-01へのDNS、FILE-SRV-01へのSMB通信も存在する。
- AD-SRV-01とFILE-SRV-01はVLAN100上の重要内部サービスである。

### 推測にとどめるべきこと

- IT-PC-02 / DEV-PC-03の通信が通常業務から逸脱している可能性。
- 認証やディレクトリ参照、ファイル共有へのアクセスを試みている可能性。
- INJ-01の外部接続と関連した内部活動である可能性。

### まだ断定できないこと

- AD認証の成功・失敗。
- 使用されたアカウント。
- 資格情報窃取の有無。
- FILE-SRV-01上のファイル閲覧・コピー・削除。
- AD設定変更。

### PCAPで確認すべき通信

| Finding | Traffic ID | 確認対象 |
|---|---|---|
| F-008 | TR-INJ02-001 | `IT-PC-02 → AD-SRV-01` DNS/53 |
| F-009 | TR-INJ02-002 | `IT-PC-02 → AD-SRV-01` Kerberos/88 |
| F-010 | TR-INJ02-003 | `DEV-PC-03 → AD-SRV-01` LDAP/389 |
| F-011 | TR-INJ02-004 | `DEV-PC-03 → AD-SRV-01` SMB/445 |
| F-012 | TR-INJ02-005 | `IT-PC-02 → FILE-SRV-01` SMB/445 |
| F-013 | TR-INJ02-006 | `DEV-PC-03 → FILE-SRV-01` SMB/445 |
| F-014 | TR-INJ02-007 | 比較用 `GA-PC-01 → AD-SRV-01` DNS/53 |
| F-015 | TR-INJ02-008 | 比較用 `GA-PC-01 → FILE-SRV-01` SMB/445 |

### 追加確認が必要な情報

- AD-SRV-01のWindows Securityログ：認証成否、対象アカウント、送信元端末、時刻。
- AD変更監査ログ。
- FILE-SRV-01の共有フォルダ監査ログ：対象ファイル、操作種別、ユーザ、送信元。
- IT-PC-02 / DEV-PC-03のイベントログ、EDRまたはアンチウイルスログが存在する場合はその記録。

### 軽い解答確認で受講者に確認するポイント

- Kerberos/LDAP通信と認証成功を混同していないか。
- SMB通信とファイル操作成功を混同していないか。
- ADとファイルサーバを重要資産として優先確認対象にできているか。
- 「何を見ると認証・ファイル操作を確定できるか」まで言えているか。

### 議論が脱線した場合の戻し方

「通信先がAD、FILE-SRV-01であることは分かります。では、認証やファイル操作の“結果”を確認する証跡は何ですか」と問い、追加ログへ戻します。

### 次の状況付与に進むために揃えておきたい認識

- IT-PC-02 / DEV-PC-03は優先確認対象候補であるが、侵害端末と確定していない。
- AD・FILE-SRV-01への通信増加は調査優先度を上げる材料である。
- 成功状態の判断にはサーバ・端末ログが必要である。

## 4.3 INJ-03：複数セグメントへの横方向通信

### この時点で確認できる事実

- IT-PC-02から `GA-PC-02` へのSMB/445通信が観測される。
- IT-PC-02から `ACC-PC-02` へのRDP/3389通信が観測される。
- DEV-PC-03から `SALES-PC-02` へのSMB/445通信が観測される。
- DEV-PC-03から `IT-PC-03` へのRDP/3389通信が観測される。
- DEV-PC-03から `DEV-PC-04` へのTCP/5985通信が観測される。
- 通信先がVLAN10、20、30、40、50へ広がっている。

### 推測にとどめるべきこと

- 横方向の探索・接続試行である可能性。
- IT-PC-02 / DEV-PC-03を起点とした影響範囲拡大の可能性。
- リモート管理機能を利用しようとしている可能性。

### まだ断定できないこと

- RDPログオン成功。
- 接続先端末でのコマンド実行。
- マルウェア実行。
- 権限昇格。
- 横展開成功。

### PCAPで確認すべき通信

| Finding | Traffic ID | 確認対象 |
|---|---|---|
| F-016 | TR-INJ03-001 | `IT-PC-02 → GA-PC-02` SMB/445 |
| F-017 | TR-INJ03-002 | `IT-PC-02 → ACC-PC-02` RDP/3389 |
| F-018 | TR-INJ03-003 | `DEV-PC-03 → SALES-PC-02` SMB/445 |
| F-019 | TR-INJ03-004 | `DEV-PC-03 → IT-PC-03` RDP/3389 |
| F-020 | TR-INJ03-005 | `DEV-PC-03 → DEV-PC-04` TCP/5985 |

### 追加確認が必要な情報

- IT-PC-02 / DEV-PC-03のイベントログ、EDRログ、プロセス生成履歴。
- 接続先端末のログオン成功・失敗イベント。
- RDP関連イベントログ。
- AD認証ログ、特権利用イベント。
- 端末間通信が通常の管理業務として許可されるものかを確認できる運用情報。

### 軽い解答確認で受講者に確認するポイント

- 通信先の「広がり」を整理できているか。
- RDP/SMB/5985の存在を「成功」や「コマンド実行」と断定していないか。
- 優先確認対象をIT-PC-02 / DEV-PC-03と接続先に絞り込めているか。
- 端末側証跡の確認を提案できているか。

### 議論が脱線した場合の戻し方

「横展開“らしい”通信はありますが、成功を示す端末側証跡はまだありません。どの端末を、何のログから確認しますか」と問い直します。

### 次の状況付与に進むために揃えておきたい認識

- 通信先が複数セグメントへ広がっていることは重要なスコープ判断材料である。
- IT-PC-02 / DEV-PC-03は優先的な端末調査候補である。
- 侵害端末・横展開成功という断定はまだしない。

## 4.4 INJ-04：ファイル共有と外部宛て通信の増加

### この時点で確認できる事実

- IT-PC-02 / DEV-PC-03からFILE-SRV-01へのSMB/445通信が観測される。
- IT-PC-02 / DEV-PC-03から `external-egress-01.example.invalid (203.0.113.77)` へのHTTPS/443通信が観測される。
- 外部HTTPS通信の近い時間帯に、AD-SRV-01へのDNS/53通信が観測される。
- FILE-SRV-01への通信と外部通信は時系列上関連を疑う材料になる。

### 推測にとどめるべきこと

- FILE-SRV-01上の情報を探索・取得している可能性。
- 外部HTTPS通信が一連の疑わしい活動に関連する可能性。
- 情報持ち出しの可能性を調査対象に含めること。

### まだ断定できないこと

- FILE-SRV-01からファイルをコピーしたか。
- HTTPSで何を送信したか。
- 情報窃取が行われたか。
- `203.0.113.77` がC2や情報窃取先であるか。
- SMB通信とHTTPS通信に因果関係があるか。

### 次の状況付与に進むために揃えておきたい認識

## 4.5 INJ-05：複数部署での業務影響の申告

### この時点で確認できる事実

- 状況付与として、複数部署から「共有ファイルが開けない」という申告がある。
- プリンタに警告文のような出力があったという連絡がある。
- GA-PC-01、ACC-PC-01、DEV-PC-01、IT-PC-02、DEV-PC-03からFILE-SRV-01へのSMB/445通信が観測される。
- 業務影響が複数部署へ広がっている可能性を示す申告があるが、原因と実際の影響範囲は未確定である。
- プリンタは `network.json` にIP付き資産として定義されていないため、警告文の出力原因をPCAP証拠として扱わない。

### 推測にとどめるべきこと

- ランサムウェア等によるファイル障害の可能性。
- それまでの不審通信と業務影響が一連のインシデントに関連する可能性。
- 影響がFILE-SRV-01または複数端末に及んでいる可能性。

### まだ断定できないこと

- ランサムウェア実行。
- ファイル暗号化の有無。
- 全端末感染。
- 実際の影響端末数。
- 共有ファイル障害の原因。
- プリンタ警告文の生成元。
- 情報窃取。

### PCAPで確認すべき通信

| Finding | Traffic ID | 確認対象 |
|---|---|---|
| F-027 | TR-INJ05-001 | `GA-PC-01 → FILE-SRV-01` SMB/445 |
| F-028 | TR-INJ05-002 | `ACC-PC-01 → FILE-SRV-01` SMB/445 |
| F-029 | TR-INJ05-003 | `DEV-PC-01 → FILE-SRV-01` SMB/445 |
| F-030 | TR-INJ05-004 | `IT-PC-02 → FILE-SRV-01` SMB/445 |
| F-031 | TR-INJ05-005 | `DEV-PC-03 → FILE-SRV-01` SMB/445 |

### 追加確認が必要な情報

- 利用者申告の対象端末・対象共有・発生時刻の一覧。
- FILE-SRV-01の状態、共有フォルダ監査ログ、対象ファイルの状態。
- IT-PC-02 / DEV-PC-03および申告端末のイベントログ、EDR / アンチウイルスログが存在する場合はその記録。
- UTM/VPN、AD、DNSの関連ログと保全状況。
- プリンタまたは印刷サービスのログが存在する場合は印刷ジョブ履歴。
- 資産管理情報を用いた影響端末のスコープ確認。

### 軽い解答確認で受講者に確認するポイント

- 「共有ファイルが開けない」「警告文らしき出力」は事実として扱いつつ、原因をランサムウェアと断定していないか。
- 原因未確定でも証跡保全・影響範囲確認・隔離候補の検討へ進めているか。
- SOC / CSIRT内へのエスカレーション理由として、複数部署の業務影響と不審通信の継続を挙げられているか。
- 隔離と証跡保全、業務影響のバランスを考えられているか。

### 議論が脱線した場合の戻し方

「ランサムウェアかどうかを確定する詳細解析ではなく、今の時点で被害を広げないために何を保全・確認・共有するか」を問い、SOC / CSIRT初任者の初動に戻します。

### 次の状況付与に進むために揃えておきたい認識

INJ-05が最終状況付与です。最終整理へ進む前に、以下がそろっていれば十分です。

- 確認済み事実と未確認事項が明確である。
- 優先確認対象が整理されている。
- 証跡保全、影響範囲確認、隔離候補、共有・エスカレーションの方針がある。
- 「ランサムウェア確定」「情報窃取確定」などの過剰な断定がない。

## 5. 攻撃の流れの整理

### 5.1 PCAP・状況付与から確認できる流れ

1. UTM(VPN)公開側へ複数の外部ホストから反復HTTPS通信がある。
2. 演習上のUTM(VPN)内部側表現からAD-SRV-01 / FILE-SRV-01への通信がある。
3. IT-PC-02 / DEV-PC-03からAD・FILE-SRV-01への通信がある。
4. IT-PC-02 / DEV-PC-03から複数VLANの端末へSMB / RDP / TCP 5985通信がある。
5. FILE-SRV-01へのSMB通信と近い時間帯に外部HTTPS通信がある。
6. 複数部署から共有ファイル利用障害等の申告が入り、複数端末からFILE-SRV-01へのSMB通信が観測される。

### 5.2 妥当な調査仮説

「外部接続を起点とした侵害が内部サービス・端末へ広がり、外向き通信や業務影響に至った可能性」を優先仮説として扱うことは妥当です。

ただし、この仮説を確定するには、VPN認証・セッションログ、AD認証ログ、FILE-SRV-01監査ログ、端末ログ、境界装置ログなどによる相関確認が必要です。

### 5.3 仮説としても慎重に扱うべき結論

- 「VPNから侵入に成功した」
- 「IT-PC-02 / DEV-PC-03が侵害端末である」
- 「横展開に成功した」
- 「ファイルを窃取した」
- 「ランサムウェアを実行した」
- 「ファイルを暗号化した」
- 「全端末が感染した」

これらは、現時点では追加証跡による確認が必要です。

## 7. PCAPから分かること / PCAPだけでは分からないこと

| 観点 | PCAPから分かる | PCAPだけでは分からない |
|---|---|---|
| VPN | 外部→UTM(VPN)の通信、時刻、回数、方向 | 認証成否、使用アカウント、脆弱性悪用成立 |
| AD | DNS/Kerberos/LDAP/SMB通信の存在 | 認証成否、資格情報窃取、AD変更 |
| ファイル共有 | FILE-SRV-01へのSMB通信、通信量・時系列 | ファイル名、閲覧・コピー・削除・暗号化の成功 |
| 横方向通信 | 複数端末・VLANへのSMB/RDP/5985通信 | ログオン成功、コマンド実行、権限昇格、横展開成功 |
| 外向き通信 | 外部IPへのHTTPS通信、時刻、送信元 | HTTPS内容、情報窃取、通信相手の実際の役割 |
| 業務影響 | 状況付与での利用者申告、関連するSMB通信 | 障害原因、影響端末数、ランサムウェア実行・暗号化 |
| プリンタ | 状況付与で警告文らしき出力の申告 | 生成元、印刷ジョブ、原因。PCAPでは新規プリンタ資産を設けていない。 |

## 8. 追加で確認すべき事項

3. **FILE-SRV-01**
   - 共有フォルダ監査ログ
   - ファイル操作、操作ユーザ、送信元端末、対象ファイル
   - 対象ファイルの状態・タイムスタンプ

   - EDR / アンチウイルスログが存在する場合はその記録

   - RDP / ログオン関連イベント
   - SMB / リモート管理関連ログ

   - ログ保全状況
   - 各資産の時刻同期状況

## 9. 初動対応案

本演習の対象はSOC / CSIRT初任者の初動調査であり、詳細復旧や高度フォレンジックではありません。模範的な初動は次の通りです。

1. **インシデント記録を開始し、時系列を一本化する。**
   - 状況付与の申告時刻とPCAP上の通信を分けて記録する。
   - 確認済み事実、仮説、未確認事項を明示する。
2. **証跡を保全する。**
   - UTM/VPN、AD-SRV-01、FILE-SRV-01、優先端末のログ保全を依頼する。
   - 不要な初期化・再起動・ログ消去につながる操作を避ける。
3. **影響範囲を整理する。**
   - IT-PC-02 / DEV-PC-03と通信先端末を優先確認する。
   - 共有ファイル障害申告の端末・部署を一覧化する。
4. **封じ込め候補を検討する。**
   - 影響拡大が疑われる場合、組織の手順に従い、疑わしい端末・通信・VPNセッション等の隔離または制限を検討する。
   - 証跡保全と業務影響を踏まえ、SOC / CSIRT上位者と優先順位を決める。
5. **重要サービスの状態を確認する。**
   - AD-SRV-01、FILE-SRV-01の可用性とログ状態を確認する。
6. **外向き通信を確認・制御候補として扱う。**
   - `203.0.113.77` への通信を調査対象として共有するが、情報窃取先・C2と断定しない。
7. **SOC / CSIRT内で緊急共有・エスカレーションする。**
   - 複数セグメントへの通信拡大と複数部署の業務影響を根拠に、原因未確定でも重大度引き上げを検討する。

## 10. SOC / CSIRT内でのエスカレーション判断

### エスカレーションを推奨する根拠

- UTM(VPN)への外部反復接続が観測される。
- AD・FILE-SRV-01という重要サービスへの通信増加がある。
- IT-PC-02 / DEV-PC-03から複数VLANへの通信が広がっている。
- FILE-SRV-01への通信と外部HTTPS通信が近接している。
- 複数部署で共有ファイル利用障害が申告されている。

### 共有すべき最低限の内容

- **確認済み事実**：IP、通信方向、ポート、業務影響申告。
- **未確認事項**：認証成功、侵害端末、情報窃取、暗号化、原因。
- **影響範囲候補**：UTM/VPN、AD、FILE-SRV-01、IT-PC-02、DEV-PC-03、通信先端末、申告部署。
- **実施済み / 予定の初動**：ログ保全、スコープ確認、隔離候補の検討。
- **追加確認要求**：認証ログ、サーバ監査ログ、端末ログ、境界装置ログ。
- **判断が必要な事項**：隔離範囲、業務影響を伴う制限、追加支援の要否。

### 共有表現の例

「複数セグメントにまたがる不審通信と共有ファイル利用障害を確認しています。VPN認証成功、侵害端末、情報窃取、暗号化の有無は未確認です。UTM/VPN、AD、FILE-SRV-01、IT-PC-02、DEV-PC-03を優先してログ保全・追加確認し、影響拡大防止のため隔離候補を検討します。」

| 共有・エスカレーション | 複数セグメントへの不審通信と複数部署の業務影響を理由にSOC / CSIRT上位者へエスカレーションする。情報窃取・暗号化等は未確認であることを明示する。 |
| 判断理由 | 単一端末の異常ではなく、境界・重要サーバ・複数セグメント・外向き通信・業務影響が連続して観測され、影響拡大リスクがあるため。 |

## 12. 初任者が間違えやすい点

| 誤解 | 修正の考え方 |
|---|---|
| 外部IP→VPN通信があるため侵入成功 | 通信の存在とVPN認証成功は別。認証ログが必要。 |
| 外部接続直後に内部通信があるため同じ攻撃者 | 時系列相関だけでは同一主体を確定できない。セッション情報が必要。 |
| Kerberos / LDAP通信があるため認証成功 | 認証関連通信の存在と成否は別。ADログで確認する。 |
| SMBが多いためファイルをコピーした | SMB通信量だけではファイル操作結果は分からない。監査ログが必要。 |
| RDP / SMBが複数VLANへあるため横展開成功 | 接続候補は分かるが、ログオン成功や実行内容は端末ログが必要。 |
| 5985への通信があるためコマンド実行 | ポートだけでは端末内処理を確定できない。 |
| SMBの後に外部HTTPSがあるため情報漏えい | 時系列相関は調査材料。ファイル操作と送信内容の追加証跡が必要。 |
| 外部ホストはC2である | 演習用外部ホストであり、PCAPだけでは相手の実際の役割・意図を断定しない。 |
| ファイル障害＋警告文なので全台ランサムウェア | 業務影響は事実だが、原因・暗号化・範囲は未確定。 |
| 原因未確定なら隔離・エスカレーションできない | 影響拡大リスクと業務影響を根拠に、未確定を明示して初動判断できる。 |

## 13. 演習担当者向けの最終解説ポイント

- この演習の「正解」は攻撃名を当てることではなく、**事実・推測・未確認を分けて初動判断できること**です。
- 受講者が「ランサムウェアだと思う」と述べること自体は問題ありませんが、根拠を「状況付与と通信からの仮説」として説明させてください。
- PCAPで見えないことを正しく認識し、追加ログ要求へつなげられれば評価してください。
- IT-PC-02 / DEV-PC-03は優先確認対象として設計されていますが、演習中に「侵害端末」と直接教えないでください。
- `192.168.100.254` はVPNクライアントアドレスではなく、ネットワーク構成図に新規内部IPを追加しないための**UTM(VPN)内部側の演習表現**です。VPN認証成功を意味しません。
- プリンタ警告文は状況付与として提示される事実であり、プリンタIPや印刷原因をPCAPから探させないでください。
