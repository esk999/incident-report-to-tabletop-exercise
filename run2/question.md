# SOC / CSIRT 初動調査・通信証跡整理演習

## 1. 演習概要

本演習は、SOC / CSIRTに配属されたばかりの初任者を対象とした、状況付与型の机上訓練です。

演習中に段階的に提示される状況付与と `training.pcap` に含まれる通信証跡をもとに、初動調査で何が事実として確認できるか、何が推測にとどまるか、何を追加で確認する必要があるかを整理します。

PCAPは「正解を探すための中心教材」ではなく、状況付与で示された事実を通信レベルで確認するための補助証跡として扱います。通信の存在だけから、攻撃成功や侵害の成立を断定しないことを重視します。

## 2. 受講者の役割

あなたはSOC / CSIRTの初動調査担当者です。

提示された状況付与と利用可能な資料を確認し、その時点での情報だけをもとに、以下を整理してください。

- 確認できた事実
- 推測されること
- まだ断定できないこと
- PCAPで確認したこと
- PCAPだけでは分からないこと
- 追加で確認すべき事項
- 初動対応案
- SOC / CSIRT内で共有・エスカレーションすべき内容
- その判断理由

特に、PCAPだけでは断定できない事項を「確認済みの事実」として扱わないよう注意してください。

## 3. 前提条件

- 対象者は、ネットワークやセキュリティの基礎知識はあるものの、PCAP解析やインシデント対応の経験が少ないSOC / CSIRT初任者です。
- 本演習は初動調査を対象とします。高度なマルウェア解析、詳細なデジタルフォレンジック、攻撃手順の詳細再現は対象外です。
- 広報対応、法的判断、経営判断、顧客対応、対外公表、行政報告の詳細は扱いません。ただし、SOC / CSIRT内で上位者や関係部署へ共有すべき事項を整理することは演習対象です。
- 状況付与で明示されていない事項は、確認済みの事実として扱わないでください。
- 不明な点は無理に断定せず、「何を確認すれば判断できるか」を整理してください。

## 4. 利用可能な資料

演習中に受講者が利用できる資料は、次のものだけです。

- ネットワーク構成図
- `training.pcap`
- その時点までに提示された状況付与カード
- 別途配布される固定フォーマットの初動調査メモ

上記以外のログや資産情報は、演習担当者から状況付与として提示されない限り、閲覧できる資料ではありません。

追加のログや端末情報などが必要だと判断した場合は、「追加で確認すべき事項」として初動調査メモに記載してください。

## 5. 状況付与の進み方

状況付与は演習中に段階的に提示されます。

後続の状況付与内容は事前には開示されません。各時点で、その時点までに提示された情報だけを用いて検討してください。

各状況付与では、まず受講者が個人またはグループで検討する時間を設け、その後、演習担当者による短い確認・軌道修正を行います。

この軽い確認は、すべての模範解答を開示するための時間ではありません。確認できた事実へ議論を戻し、推測と断定を分け、次の状況付与へ進むために必要な認識をそろえることを目的とします。

## 6. 演習時間

演習全体は **2〜4時間程度** を想定し、標準は **約3時間** です。

時間には、次の内容が含まれます。

- 演習説明
- 各状況付与での個人またはグループ検討
- 各状況付与後の軽い確認・軌道修正
- 最終的な初動調査内容の整理
- 全体解説
- 振り返り

各状況付与の検討時間は、提示される状況付与カードに従ってください。

## 7. 各状況付与で考えるべき観点

状況付与が提示されるたびに、以下の観点で整理してください。

### 7.1 確認できた事実

状況付与に明示された事実と、PCAPから直接確認できた通信事実を分けて整理してください。

PCAPから確認できる代表的な事項には、次のようなものがあります。

- 送信元IPアドレス
- 宛先IPアドレス
- 通信時刻
- 通信回数や継続時間の傾向
- プロトコル
- 宛先ポート
- 通信方向
- 通信の有無

### 7.2 推測と未断定事項

観測事実から考えられる可能性は、「推測」または「仮説」として記載してください。

次のような事項は、PCAPだけで確認済みの事実とはしません。

- 認証の成功・失敗の最終判定
- 認証情報の窃取
- ファイルの閲覧・コピー・削除
- 情報窃取
- 端末上で実行されたコマンドやプロセス
- マルウェア実行
- ファイル暗号化の実行
- C2通信の成立
- 攻撃者の意図
- 特定端末が侵害されたという確定判断

これらを判断するには、PCAP以外のログや端末・サーバ側の調査が必要になる場合があります。

### 7.3 追加で確認すべき事項

不足している情報を明確にし、「何を確認すれば次の判断ができるか」を整理してください。

実際には配布されていないログを、確認済みの情報として扱わないでください。必要なログや情報は、追加確認事項として記載します。

### 7.4 初動対応案

現時点で必要と考える初動対応を、根拠とともに整理してください。

長期的な復旧計画や詳細な再構築ではなく、初動段階での確認、証跡保全、被害拡大防止、継続監視、共有・エスカレーションを中心に考えてください。

### 7.5 共有・エスカレーション

SOC / CSIRT内で共有すべき事項と、上位者や関係部署へのエスカレーションを検討すべき事項を整理してください。

断定できていない内容を共有する場合は、「確認済み」「推測」「未確認」など、情報の確度が分かる表現を使用してください。

## 8. 提出物

別途配布される固定フォーマットの初動調査メモに、以下を整理して記入してください。

- 確認できた事実
- 推測されること
- まだ断定できないこと
- PCAPで確認したこと
- PCAPだけでは分からないこと
- 追加で確認すべき事項
- 初動対応案
- SOC / CSIRT内で共有・エスカレーションすべき内容
- 判断理由

演習終了時には、各状況付与で記録した内容を踏まえて、現時点での初動調査結果としてまとめてください。

## 9. 注意事項

- 状況付与で提示された情報と、PCAPから直接確認できる情報を混同しないでください。
- 通信が存在することと、その通信によって認証・侵入・ファイル操作などが成功したことは別です。
- 「ありそう」「攻撃らしい」という印象だけで事実認定しないでください。
- PCAPだけで分からないことは、そのまま「未確認」と整理してください。
- 追加で必要なログや調査項目を具体化することも、重要な演習成果です。
- Wiresharkの特定フィルタを当てて答えを探すこと自体が目的ではありません。通信の送信元・宛先・時系列・プロトコル・方向・頻度などを、状況付与の事実と対応付けて確認してください。
- 攻撃手順の再現や、攻撃を実行するための詳細な検討は行いません。
- 議論が広報、法務、経営判断、長期復旧、高度な解析へ広がった場合は、SOC / CSIRTの初動調査で今確認すべきことへ戻してください。
